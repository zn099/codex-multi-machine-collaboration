# 让远端聊天显示出来

## 先确认当前界面加载了什么

在设置的连接页面确认目标 SSH 主机已启用并连接成功，然后回到聊天列表。检查当前的主机、项目分组或筛选范围，找到目标电脑上的一条已有聊天。具体布局以安装的客户端为准，不假定所有版本都有相同的按钮。

打开这条聊天，核对原始标题、所属电脑和项目，以及能否读到原来的内容。活动中的聊天还应能显示新的状态和输出。用户自己在这条聊天中发送后续要求后，回复也应继续出现在这里。

如果当前环境提供主机、项目和聊天读取工具，可用它们辅助判断：远端究竟没有返回聊天，还是界面没有显示出来。使用工具返回的真实标识；不从 SSH 别名猜内部 hostId，也不把聊天摘要当成标题。仅需要核对时读取必要元数据，不批量导出历史。

## 连上了，但旧聊天没出现

1. **连接的电脑是否正确。** 核对 SSH 实际地址、主机与运行位置，排除别名指向另一台电脑。
2. **登录的用户是否相同。** 原来在账户 A 使用 Codex，SSH 却登录账户 B，可能读到另一份历史。Windows 用户改名后，账户名和个人目录名也可能不同。
3. **远端服务读的是哪份数据。** 核对实际启动的 Codex、运行用户、profile 及 `CODEX_HOME`；只读取必要路径和元数据，保留原有认证配置。
4. **聊天是否被当前显示范围挡住。** 检查主机或项目筛选，以及需要查找的聊天是否已归档。用客户端现有入口查看，不为显示而擅自移动或取消归档。
5. **当前客户端与远端服务是否支持该来源。** 查连接日志和匹配版本的官方说明。分别记录“服务返回了聊天”“界面显示了聊天”“打开后可继续”的实际结果。

各台电脑的聊天记录仍由各自的主机保存，当前客户端把它们展示在一起。排查时围绕正确的历史来源和显示入口处理，不复制整个 `.codex` 目录，也不拿新建的同名聊天顶替原记录。

## 能看历史，但进度不更新或发不出消息

先确认连接仍有效。缓存的旧记录不能证明主机当前可达；必要时回到 [连接排查](remote-computers.md)检查网络、SSH 和远端服务。

连接正常后，核对这条聊天在实际服务中的状态和执行环境。若 SSH 能启动新 CLI 会话，但客户端中的原聊天仍无法继续，就明确记录这个差别，继续查原聊天所连的服务。新启动 `codex` 不等于已恢复原聊天。

短暂掉线后先重连原主机，打开原聊天确认上次指令是否已经收到，再决定是否补发，避免同一任务执行两次。
