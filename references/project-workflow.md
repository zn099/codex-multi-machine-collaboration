# 项目执行

用于建立工作约定、整理项目、规划和验收任务。以下是可采用的默认方法；用户和项目已有明确选择时沿用，不强行迁移。

## 开工只读必要入口

读取项目根目录及当前目录适用的 AGENTS.md，再读它指定的 README 或状态入口。定位本次输入、源码或成果，不遍历整个用户目录、不默认扫描全部聊天。

名称含糊时先查已有项目和文件。当前聊天的临时工作目录不自动成为正式项目根目录。项目未选择云同步时先本地工作；只有准备创建新的持久项目且选择尚不明确时，询问一次是否同步，同时继续可独立的本地工作。

任务复杂时，用简短计划标明依赖和验收，例如“核对既有入口 → 修改目标实现 → 用实际输入检查 → 更新已有状态”。不要把每次工具调用变成计划项。

## 文件组织的默认做法

- 按项目内容组织，跨日期、跨聊天沿用固定根目录。项目根由用户选择，不硬编码作者路径。
- 文档类项目可用 outputs/ 保存正式交付、work/ 保存必要脚本和中间产物；代码项目保持正常源码结构。
- 新增文档主题不足三个需保留文件时保持扁平；达到三个才按需要分类。正式交付和工作文件分别计数，不为了建目录凑文件。
- 同一逻辑文件直接更新固定路径，不自动生成日期后缀、v2、final-final 或备份副本。明确要求保留版本时才另存；已有 Git 历史和用户保留的快照照常保留。
- 原始数据、不同实验结果和不同用途的同名文件不能混为“旧版本”。修改文档源文件后，需要的导出格式同步更新。
- 移动文件之前检查引用、脚本路径、虚拟环境入口及配置依赖。迁移后只删除已确认搬完的旧入口和空目录；不批量清理未知内容。
- 简单问答和状态解释不额外落盘。临时文件只清理本次产生且已无用途的部分。

这些规则适用于成果组织，不约束工具正常运行所必需的 .git、技能目录、环境或缓存结构。

## 实施与纠错

先判断用户建议是否能达到目标。例如“SSH 别名与 Windows 用户名相同”并非要求；“远端在线”不能证明应用可用。指出具体错误或尚未验证的环节，完成最小修正；涉及研究问题、结论或不可兼得的方案才集中询问。

实现只覆盖当前任务。不顺带增加管理服务、监控平台、复杂配置框架、签名系统或自动归档。专业技能只在其领域真正需要时使用。

耗时任务报告已学到什么、下一步消除什么不确定性。依赖用户输入的步骤暂停，其他独立步骤继续；等待时不能把默认选项当作已批准。

## 验收与收工

| 交付 | 有意义的验证 | 不足以验收的证据 |
| --- | --- | --- |
| 代码 | 相关用例或既有检查，必要时实际输入输出 | 只看到命令退出、只看文件存在 |
| 文档 | 内容核对与按格式需要的实际渲染 | 只设置字体名称、只保存成功 |
| 远程接入 | 远端真实身份、工作目录、所需工具可执行 | 管理页面显示在线 |
| 项目同步 | 推送成功且目标分支包含本次提交 | 仅本地 commit |
| 科研结果 | 数据与计算可追溯，区分仿真、训练、实机 | 多个模型赞同同一推断 |

低影响修改不机械增加测试；运行足以证明本次行为的检查。存在故障时明确具体阶段、实际错误、已尝试步骤与未完成项。

持续项目在已有 README 的状态段记录四项即可：已验证结果、当前决定、未解决项、下一步。长期约定写进 AGENTS，不把全部诊断日志堆到规则文件。检查完成后简短交付，不继续制造报告。
