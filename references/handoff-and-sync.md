# 交接与同步

先明确用户要同步的是项目文件、工作约定、执行进度还是某一条聊天；四种对象采用不同机制。

## “记忆”不是一个文件夹

| 信息 | 合适的保存或读取方式 |
| --- | --- |
| 个人偏好、项目约定 | 对应作用域的 AGENTS.md |
| 可复用操作方法 | Skill 及按需参考 |
| 当前项目进度、结果入口 | 已有 README／状态入口 |
| 特定聊天的历史与活动状态 | 产品提供的聊天读取、继续或迁移能力 |
| API 密钥、登录、SSH 私钥 | 各设备自己的认证机制；不作为项目资料同步 |

SSH 登录能读取授权范围内的远端文件和启动进程，不会自动把所有聊天记忆合并到当前聊天，也不自动接管另一桌面窗口中的会话。

确实要继续某条聊天时，用实际可用的产品工具查找并确认对象。读取状态与发送新任务是不同操作；发送、迁移或中断须有相应授权。不同执行端的功能可用性需现场确认，不能手工复制会话数据库来假装完成迁移。

## 两种多电脑方式

**固定执行端：** 项目和依赖保留在一台主机，其他电脑通过 SSH 或受支持的远程界面操作。适合依赖重、数据大或有 GPU 的项目。先验证执行端身份和目录，再下达任务。

**每台电脑各有工作副本：** 使用已选择的 Git 远端同步源码和必要材料；各机独立安装依赖并配置认证。适合离线编辑。切换写入设备前明确未提交内容和远端状态。

选择满足任务的方式，不必互相复制整个用户目录。可按项目组合这两种方式；远程登录成功不意味着 Git 已同步。

## 项目选择了 Git 同步时

1. 确认仓库根、分支、工作区和远端，优先使用项目已有同步脚本。
2. 开工取回更新，按项目约定快进合并。未提交修改、分叉、认证或网络失败时保护现有内容，解释具体阻碍；离线继续依用户授权处理，不声称已拉取。
3. 只提交本次完成的文件，不夹带其他聊天未完成的修改。不要强推、硬重置或自动选某一方覆盖冲突。
4. 收工获取新增远端提交，处理后推送；核对目标分支和本地状态。区分“本次提交已同步”与“整个工作区无待处理内容”。

本地项目无需履行远端流程；存在 Git 配置、安装技能或生成文档都不是上传授权。已明确选定同步后，不每次重新询问。

## 足够继续工作的交接

优先更新项目既有状态段，不新建平行记录。跨设备时包含：

```text
项目：名称与接收端实际路径
执行端：已验证的主机别名、用户、运行环境
代码状态：分支、已提交/未提交内容、是否已同步
已验证：结果及对应文件/命令
未完成：具体错误或缺失条件
下一步：一项可执行动作及必要验收
```

后续补充一般是在修正当前任务；接续时保留原目标、约束和已做工作，避免重新配置全部环境。

迁移运行中的聊天前，核对产品的匹配项目要求与中断行为及用户授权；不能把“查看进度”理解为“迁移执行位置”。参见 [OpenAI：远程连接与聊天交接](https://learn.chatgpt.com/docs/remote-connections)。

## 将个人方法开源

先写可独立阅读的方法、模板和适用条件，使用虚构占位值。真实设备表、完整 SSH 配置、认证、聊天记录和业务资料留在原项目。独立发布方法库不改变其他项目的云同步选择。

公开内容准备并检查后，在已授权目标仓库发布。核对归属、可见性、许可和文件范围；授权不足时展示具体可审阅结果再询问。工具缺少建仓或登录能力时说明具体缺口，不把本地仓库称为 GitHub 已发布。
