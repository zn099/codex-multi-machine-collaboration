# 项目工作约定

## 目标与入口

- 项目目标：填写当前项目要完成的事情。
- 权威项目根：由使用者选择；跨设备时分别记录接收端实际路径。
- 先读入口：优先使用已有 README 及其状态部分。
- 执行端：本机或已验证的远程主机；不把认证材料写入本文件。

## 文件与修改

- 延续源码结构；文档交付放 outputs/，必要中间资料放 work/。
- 新主题不足三个需保留文件时保持扁平；程序必需目录和已有固定路径除外。
- 同一成果固定路径覆盖；原始数据、独立实验和明确保留的版本另行保护。
- 迁移前更新引用；只清理已确认迁移完毕的旧入口与空目录。

## 同步选择

- 默认仅本地。明确选择远端后填写服务、仓库和分支；未选择前不上传。
- 已启用同步的项目开工按约定快进更新，收工定向提交并推送；不强推、不覆盖其他任务修改。
- 不上传认证、完整聊天记录、用户目录或可重建的大型环境。

## 执行与验收

- 当前任务的输入、交付和验收条件应明确；已授权常规工作直接完成。
- 检查方法：填写实际存在且与项目相关的命令或人工检查，不虚构测试。
- 并行方式：沿用使用者与运行环境的约定；同一文件保持明确修改负责人。
- 当前状态维护在已有 README：已验证结果、决定、未解决项、下一步。简单问答不更新状态。

## 项目专有约定

按需填写语言、字体、科学假设、硬件范围或禁止改动事项；不把某个项目的偏好扩成所有项目的硬性要求。
